## Skalierbarkeitsanalyse (low-level chain, v0.2.0 — verified state)

Measured/inspected on the tagged v0.2.0 code; each finding is grounded in the implementation:

| Component | Mechanism | Scales well to | Bottleneck at production scale |
|---|---|---|---|
| RDMO pull (`regimo_core/lib/rdmo.py`) | paginated list (page_size=100, follows `next`) + one maDMP render per project | hundreds of projects | 1 synchronous maDMP-render HTTP call per project **per round**, even unchanged (steady state = N+1 calls) |
| Change detection (`sync/engine.py`) | SHA-256 over canonical maDMP + SMS-extras bytes | any N | state file is a single JSON — concurrent engine runs are uncoordinated (no lock) |
| Fuseki write (`lib/fuseki.py replace_all`) | clear default graph + re-upload every artifact, self-healing on next round | dozens of projects | O(total triples) rewrite per change; per-project deletion unreliable because artifacts use **blank nodes** |
| Kafka bus | single broker, `edo.*` topics with 3 partitions, semantic headers (socket_id, ontology_uri, project_id, schema_id, timestamp, lineage) | dev/test load | no replication, no persistent storage — broker loss loses history |
| socket-ux bridge (`databus.py`) | per-topic ring buffers (deque maxlen=100), dedup by (topic, partition, offset) | UI liveness | in-memory only: restart wipes buffers; `_seen` dedup sets grow unbounded over long uptimes |
| UI | SSE + REST bridge through Vite proxy (dev) / socket-ux serving (prod) | single-user workstations | Vite dev server is dev-grade; production path (built assets via socket-ux) exists but is not the exercised default |
| Test/CI | 45 socket-ux + 34 core unit tests, opt-in live-broker test, vue-tsc/eslint/oxlint | current team | no CI pipeline; no Playwright e2e in automation; SHACL validation is manual, not in the sync loop |

**Net assessment:** the architecture is dimensioned correctly for the feasibility study (1–3 projects, single user). First real friction appears at ~10² projects (steady-state HTTP cost, whole-graph rewrite) and at operational uptime (ring buffers, no CI). Nothing blocks the high-level run; the fixes below are cheap if done before productive operation.

## Lessons learned (low-level run, worth carrying into the high-level run)

1. **Digest-stable state was the single best design decision** (CF1): "no changes" became verifiable in one line, and re-runs are idempotent — keep this pattern for any future pipeline stage.
2. **Semantic message headers paid off immediately**: the Bus drawer/live tracker (CF1-012) could filter and group messages with zero extra infrastructure because every event carries `schema_id`/`project_id`/`lineage` — direct feasibility evidence for [[CF2-008]] (semantic search over bus messages).
3. **Fix root causes, not symptoms** — the three expensive bugs of the cycle were all root-caused: invisible icons (missing font → bundled `mdi-svg`), resurfacing Weatherstation data (verify-stage replay graphs → `DROP SILENT`), stale drawer after SSE reconnect (refetch on reconnect).
4. **Unit-green ≠ visually correct**: the icon bug passed every test. The high-level run must include a browser-level check of every UI artefact (a Playwright e2e smoke test would mechanise this).
5. **Spec-level fallbacks beat data migrations**: the `hasContact` candidate-list fallback (CF2-007) fixed every DOI-imported project without touching stored data.
6. **No-demo-data policy (CF1-013)** exposed real empty-state gaps that fixtures had hidden — high-level run should therefore start with an *empty* RDMO and build up, not from a pre-seeded instance.

## Empfehlungen für Produktivbetrieb (preliminary, ordered by cost/benefit)

1. **Skolemize blank nodes** into stable project IRIs → enables per-project graph updates and removes the O(total) `replace_all` rewrite. — *Done 2026-11-23, see activity log.*
2. **Add a simple sync lock** (file lock or leader flag) before any second engine instance can exist.
3. **Bound the bridge `_seen` dedup sets** (evict with the buffer) — one-line fix for unbounded memory.
4. **Persist bus history** (compacted Kafka topic or DB sink) — ring buffers are UI-only; audit needs a durable record.
5. **Stand up CI** for the three suites + type-check/lint; add the live-broker test as a nightly.
6. **Fold SHACL validation into the sync loop** (validate artifacts before the per-project upsert).
7. Production Kafka: replication + persistent volumes; serve the UI as built assets from socket-ux.
