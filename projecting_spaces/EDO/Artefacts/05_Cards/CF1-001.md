## Business Context
> **As a** Researcher / socket
> **I want to** Publish machine-actionable metadata (the maDMP document) as the first payload onto a shared, ontology-aware bus
> **So that** downstream sockets can consume DMP metadata with standardised headers and schema-based (de)serialisation

## Acceptance Criteria
- [x] **Scenario:** Kafka bus is up via docker-compose
	- **Given:** Docker + docker-compose are available on the host
	- **When:** `docker compose up -d zookeeper kafka` is run
	- **Then:** Zookeeper (2181) and Kafka (9092) report healthy and start cleanly
- [x] **Scenario:** DMP topic is created
	- **Given:** The bus is running
	- **When:** The topic is provisioned (explicitly or auto-created on first produce)
	- **Then:** Topic `edo.dmp.v1` exists (3 partitions, matching `num.partitions=3`)
- [x] **Scenario:** Message header/metadata contract defined
	- **Given:** `regimo-core` is the shared bus library
	- **When:** `core/interfaces/message.py` is created
	- **Then:** It defines the ontology-aware header metadata (socket_id, ontology_uri, project_id, schema_id, timestamp, lineage) and a helper to build headers from a maDMP payload
- [x] **Scenario:** JSON bus client with produce/consume
	- **Given:** `regimo-core` provides shared bus logic
	- **When:** `core/lib/bus.py` is created
	- **Then:** It exposes a JSON `BusClient` (producer/consumer) that enforces the header contract plus a `publish_maDMP(path)` convenience that publishes `{"dmp": ...}` to `edo.dmp.v1`
- [x] **Scenario:** maDMP round-trip on the bus
	- **Given:** The bus is running and the payload file exists
	- **When:** `Measurement_02.render.json` is produced to `edo.dmp.v1` and consumed back
	- **Then:** The returned JSON parses, keys are present, emits the maDMP first payload intact
