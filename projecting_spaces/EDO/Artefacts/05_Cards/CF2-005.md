## Decision (2026-11-19)

**Where — in the internal format, as first-class relations (not in NovaCrate, not a source merge).**
The DMP`Dataset` is linked to the SMS `Sensor` by `prov:wasGeneratedBy`; the `Sensor` links to its `MeasuredProperty[]` by `sosa:observes`. Both slots already exist in the internal-format schema (`Dataset.was_generated_by`, `Sensor.observes`, `Dataset.observes`) and in the spec ERD (§2). The source documents (maDMP JSON / SMS JSON:API) are **not** merged — the link lives in the EDO pivot graph only, so DMP and SMS provenance stay separable (R7).

**How — reference (IRI/blank-node), not merge and not annotation.**
`Dataset prov:wasGeneratedBy Sensor` is a reified graph edge (a reference to the Sensor node), not a copying of sensor fields into the Dataset and not a textual annotation. **Join key = the sensor PID (handle).** Today that PID appears twice: (a) machine-readable, as the SMS `Sensor.edo:identifier` (`21.11157/…`, S5), and (b) only as free text `PIDINST: …` in the DMP `dataset/description` (gap register #18, P30). The linkage therefore needs the DMP side of the PID to become machine-readable before it can be **populated and map-able** (see F12).

**Which metadata is linked:** the `Dataset → Sensor` edge, and through `Sensor.sosa:observes`, its full `MeasuredProperty[]` (quantity, unit, range, accuracy, resolution, sampling media, compartment, aggregation, SMS-CV URIs). Optionally `Dataset.realized_as → MeasurementSeries`, which itself `prov:wasGeneratedBy` the Sensor.

**Bidirectional?** Yes in the schema — both `Dataset prov:wasGeneratedBy Sensor` (dataset side) and `Sensor sosa:observes MeasuredProperty` (sensor side) exist. Today only the sensor side is ever emitted (standalone Sensor node); the dataset side is never populated (P30 logs a rule but adds no triple).

**Consequence for F12 (map-ability):** once the DMP carries the sensor PID machine-readably (structured instrument-PID question — new catalog, CF2-001/002 — or an ELN/resolvable PID), the `prov:wasGeneratedBy` slot becomes a normal slot derivation and P30 **moves into the map**. Until then the link is provisioned on the EDO layer / exemplified manually. See fragment `07_Fragments/scripts/internal-format/linkage-strategy.md` and the example instance.
