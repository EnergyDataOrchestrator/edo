## Business Context
> **As a** research fellow curating a dataset and a data steward confirming its semantics
> **I want to** bind the columns and categorical cell values of a dataset to ontology terms (target IRI, QUDT unit) and let the steward accept them
> **So that** the dataset becomes semantically grounded machine-actionably — the CCA bounded context of the spec — instead of stopping at dataset-level seeds

Follow-up to [[UPL-003]] (dataset-level seed view + NovaCrate highlight link). This card lifts the CCA workspace from dataset-level seeds to the **column & cell** level — the core responsibility of the CCA bounded context (`SPEC-bounded-contexts-and-ui.md` §CCA: column→`target_ontology_uri` + `qudt_unit_uri` + `confidence_score` + `review_status SUGGESTED/ACCEPTED/REJECTED`; cell→CV-IRI). It is also the planned resolution of the Phase-3 blocker `PLAN.md` §4 #2 (*"CCA contract: who owns the column/cell structure and the ontology term recommendation endpoint"*).

**Verified seed (2026-11-23):** the internal format already carries a **column structure for instrument-backed datasets**: `dcat:dataset → prov:wasGeneratedBy (sosa:Sensor) → sosa:observes` properties with `smscv:measuredQuantity`, `dcterms:title`, `edo:unit` and measuring ranges. The derived crate already emits each such property as a `sosa:ObservableProperty` entity (`components/socket-ux/src/socket_ux/crate.py`, `build_crate`) — column selections can therefore reuse the UPL-003 highlight mechanism with **existing crate entities**. For **non-instrument datasets** (e.g. the live literature-type projects) the graph contains **no column structure at all** — columns would come from actual data files (regimo/EDR territory).

## Plan (staged)

**Stage 1 — seeds from the internal format (no backend contract needed).**
- Extend `ProjectCcaView.vue` to the three-pane workbench: dataset list | column binding table | term inspector. Columns per dataset: for instrument-backed datasets, one row per `sosa:observes` property (name, measured quantity, unit, measuring range) — with an honest empty state otherwise ("no column structure known — comes from the data file", CF1-013).
- Reuse the UPL-003 highlight link: selecting a column highlights the matching `sosa:ObservableProperty` entity that `build_crate` already puts into the crate.
- Cell level is **not** part of Stage 1: no cell values exist in the graph.

**Stage 2 — real data-file columns (contract decision, see below).**
- Decide the owner of the column structure, extend the internal-format LinkML schema (`projecting_spaces/EDO/Artefacts/07_Fragments/scripts/linkml/05_P05_S05_internal-format-schema.yaml`) accordingly, and sync it through regimo-core into the graph.
- Cells (distinct categorical values → CV terms) follow the same ingestion decision.

**Stage 3 — recommendation + review workflow (backend work).**
- Ontology term recommendation: OHS-style search endpoint in socket-ux backed by regimo-ontology (search over labels/definitions of the ontology + CVs); `confidence_score` presentation.
- Review workflow with UPL-002 capabilities: fellow drafts annotations (`SUGGESTED`), steward accepts (`ACCEPTED`)/rejects (`REJECTED`); draft annotations stored via the UPL-001 OCC pattern (revision tokens, If-Match/409); commits publish `edo.cca.v1` events (topic not yet published by any socket — backend work).

## Decision Proposal — Column-Structure Ownership (Stage 2)

*Status: proposed 2026-11-23.* Grounded in the verified state: the graph has seeds only for instrument-backed datasets; nothing else knows about columns.

| Option | Mechanism | Fits regimo/EDR? | Effort | Consequence |
|---|---|---|---|---|
| **A — regimo publishes column metadata** | At publish time (UC1/UC2), regimo extracts CSV headers (+ dtype/unit hints) and writes them into the internal-format graph; socket-ux only reads | ✅ single writer, provenance for free (the publisher knows the file) | Medium — schema extension + regimo change | Columns exist in the graph for every published dataset; annotation is offline/async |
| **B — socket-ux reads files on demand** | socket-ux opens the distribution's `contentUrl` and sniffs headers at request time | ⚠️ duplicate responsibility, I/O at request time, no provenance of *who* derived the columns | Low initially, drifts later | Fast demo, but a second implementation of "what is a column" |
| **C — annotation UI without file access** | Stay with Stage-1 seeds; humans enter columns manually as drafts | ✅ no pipeline change | Minimal | Not scalable, but unblocks the review workflow immediately |

**Recommendation: staged — C immediately inside Stage 1/3, A as the target for Stage 2.** C keeps the fellow/steward review workflow unblocked while the regimo ingestion is built; A is the only option that keeps one owner of the column structure and gains provenance for free. B is rejected as a standalone (second source of truth), but its header-sniffing logic can be reused inside regimo when A is implemented.

## Acceptance Criteria
- [ ] **Scenario:** Instrument-backed dataset shows its columns
	- **Given:** A synced project whose dataset is backed by an SMS sensor with `sosa:observes` properties
	- **When:** The CCA workspace is opened
	- **Then:** One column row per observable property (name, measured quantity, unit, range) is displayed and selecting it highlights the `sosa:ObservableProperty` entity in the editor
- [ ] **Scenario:** Non-instrument dataset is honest
	- **Given:** A dataset without sensor lineage (e.g. literature datasets)
	- **When:** The CCA workspace is opened
	- **Then:** The column pane shows the empty state "no column structure known — comes from the data file" without fabricated data
- [ ] **Scenario:** Draft annotation (Stage 3)
	- **Given:** Role `fellow` and a dataset with columns
	- **When:** A column is annotated with an ontology term
	- **Then:** The annotation is stored as `SUGGESTED` via the OCC pattern (If-Match), and a `steward` can move it to `ACCEPTED`/`REJECTED`; every committed annotation state emits `edo.cca.v1`
- [ ] **Scenario:** Term recommendation (Stage 3)
	- **Given:** A column name is being annotated
	- **When:** The term picker is used
	- **Then:** An OHS-style search endpoint (socket-ux, backed by regimo-ontology) returns ranked candidates with labels/definitions
- [x] **Scenario:** Column-structure ownership decided
	- **Given:** The decision proposal above
	- **When:** It is accepted
	- **Then:** The internal-format schema change (if any) is specified in this card before implementation
