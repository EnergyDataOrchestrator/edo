## Business Context
> **As a** data steward or research fellow
> **I want to** in the CCA workspace a dataset together with its distributions and data-protection flags to locate in the RO-Crate editor at the same time
> **So that** semantic annotation starts from the real data structure and I can see which entity of the crate I am annotating — instead of editing abstract JSON blindly

Created from the **vue-frontend uplift planning** (`frontend/vue-frontend/docs/uplift/PLAN.md`, **Phase 3**; specification `docs/uplift/SPEC-bounded-contexts-and-ui.md` §CCA view). First increment of the CCA bounded context: the workspace is no longer a placeholder, but shows the actual seeds of the semantic annotation.

**Verified constraint (2026-11-23):** the embedded NovaCrate editor (interface v1, `docs/iframe-interface.md`) has **no hover/selection event** — the parent cannot detect what is being hovered (`ENTITY_HOVERED`/`ENTITY_SELECTED` do not exist in v1, cross-origin DOM access is blocked). The current leverage is therefore the reverse direction: the CCA selection sends `UPDATE_CRATE` with a transient highlight marker into the editor. Interface v1 messages: NovaCrate→parent `READY`, `CRATE_CHANGED`, `GET_CRATE_RESPONSE`; parent→NovaCrate `LOAD_CRATE`, `UPDATE_CRATE`, `GET_CRATE`.

## Plan

1. **Backend enabler — per-dataset crate entities.** `build_crate` in
   `components/socket-ux/src/socket_ux/crate.py` treats `dcat:dataset` only as a
   single dict; with a list (RDMO projects with several datasets, pyld compacts
   one-element lists to the bare node) it silently falls back — no dataset
   entities, no highlight targets. Extension: one `Dataset` entity per
   `dcat:dataset` (title, description, keywords, identifier,
   `edo:personalData`/`edo:sensitiveData`), distributions as `MediaObject`
   entities (`encodingFormat`, `contentUrl`, `edo:dataAccess`), root as
   collection with `hasPart`; sensor/observes-union, license, contact and
   funder remain. Normalize list/dict robustly (`_nodes`/`_texts`).
2. **Highlight marker as library.** `frontend/vue-frontend/src/lib/crateHighlight.ts`:
   marker property `https://w3id.org/edo/terms/editorHighlight` on the target
   entity (`withHighlight`), removal from all entities (`stripHighlights`);
   marker is transient — it never enters `currentCrate` and never the OCC commit.
3. **TheEditor as bridge.** Exposed `highlightEntity(entityId | null)` sends
   `UPDATE_CRATE` with the marker built from the clean `currentCrate.metadata`
   (UPDATE_CRATE overwrites conflicting local changes in NovaCrate — always
   build from the freshest clean document). `CRATE_CHANGED` ingest strips
   markers; identical documents (marker echo without real change) do not flag
   the OCC draft dirty.
4. **CCA workspace view.** `views/ProjectCcaView.vue` on `/projects/:pid/cca`:
   left pane datasets + distributions (clickable seeds, flags, keywords),
   right pane the embedded editor (`TheEditor embedded`). Click →
   `highlightEntity`; honest status chip (`highlighted in editor` / `no
   matching crate entity`). No columns/cells yet — this increment covers
   dataset-level seeds only.

## Acceptance Criteria
- [x] **Scenario:** Dataset selection highlights in the editor
	- **Given:** A synced project with ≥ 1 dataset and a derived crate
	- **When:** A dataset (or distribution) is selected in the CCA workspace
	- **Then:** The editor receives an `UPDATE_CRATE` with the marker on the matching entity (`@id`); NovaCrate confirms via `CRATE_CHANGED`
- [x] **Scenario:** The marker remains transient
	- **Given:** A highlight was sent
	- **When:** The crate is read via `GET /api/v1/projects/{pid}/crate`
	- **Then:** No `editorHighlight` marker is present in the graph; the OCC revision token is unchanged
- [x] **Scenario:** Several datasets exist
	- **Given:** An RDMO project with several `dcat:dataset` entries
	- **When:** The crate is derived
	- **Then:** One `Dataset` entity per dataset exists and is selectable
- [ ] **Scenario:** Column/cell level (out of scope of this increment)
	- **Given:** Column structures in the internal format
	- **When:** A column is selected
	- **Then:** The matching entity is highlighted — blocked, the internal format does not yet expose columns (socket-ux dependency, PLAN §4 #2)
