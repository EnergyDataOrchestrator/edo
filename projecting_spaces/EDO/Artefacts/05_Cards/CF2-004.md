  **How the maps carry the logic.** Each LinkML Map is a linkml-map
  TransformationSpecification (linkml-map 0.5.2, version-pinned): class
  derivations keyed by target class with `populated_from` = source class; slot
  derivations either `populated_from` (direct copy, recursing into nested
  derivations) or `expr` (restricted LinkML evaluator: null-propagating
  operators, `case()`, schema-bound attribute access). The four maDMP CVs are
  `mirror_source` pass-through enum derivations. The translation tables of the
  catalogue are compiled into `case()` expressions (role → RDA CV = P8, format
  → IANA media types = P34, datasheet overrides = S10–S12), so the map files —
  not the tool — are the single container of the transformation logic. Export
  deviations are reconciled inside the map via `source_schema_patches` (F4:
  `project` as list; F5: `license` as `LicenseRef` array). Tool-side (not
  expressible in a map): JSON:API envelope unwrapping/filtering, device IRI
  minting (S6), and the schema-driven serialiser (predicates from slot
  `mappings`, datatyping from ranges, types from `class_uri`).
