## Business Context
> **As a** fellow or steward editing project metadata in the vue-frontend (or later the EdoClient)
> **I want to** concurrent edits to the same record be detected and resolvable instead of silently overwritten
> **So that** two people working on the same project never clobber each other's changes and every conflict is an explicit, explainable decision

Created from the **vue-frontend uplift planning** (`frontend/vue-frontend/docs/uplift/PLAN.md`, **Phase 5**; specification `docs/uplift/SPEC-bounded-contexts-and-ui.md` §3 — draft-vs-committed state model and OCC protocol). Phases 0–2 of the uplift (shell, ADP, FEP) are implemented on the `uplift` branch; this card opens the backend-dependent part: **state model, revision tokens, optimistic concurrency**.

**Current state (verified):** the frontend has *no* concurrency control — `currentCrate.ts` and the `/values` view hold plain client state, socket-ux returns no `ETag`, no `If-Match` is sent anywhere, and the shared SSE connection (`lib/live.ts`, Phase 0) carries no revision semantics.

---

## Plan

1. **Prerequisite — stable, digest-addressable state (regimo-core, [[REV-001]]).** Revision tokens are `rev:<seq>:sha256:<64-hex>`; the `sha256` part requires content digests and stable (skolemized) per-project graph URIs. Until the sync engine exposes `plan_digest_sha256` and skolemizes blank nodes, only the `seq` half is implementable.
2. **socket-ux: revision tokens per editable slice.** Define the editable scopes (first slice: the RO-Crate draft per project, `fep:crate:<pid>`; second: per-dataset annotation sets once CCA exists). Each `GET` returns `ETag: "rev:<seq>:sha256:<hex>"` + `revision_token` in the body; each mutating request is checked against `If-Match`. Token state persists across socket-ux restarts (sidecar file or derived from stored digests + an event-sourced sequence).
3. **socket-ux: 409 Conflict contract.** On mismatch: `409` with `{current_revision_token, current_digest_sha256, updated_by, updated_at, server_record, field_conflicts}` — no partial write.
4. **vue-frontend: `useOccResource` composable.** Holds the base token, injects `If-Match`, parses the 409 body, and drives the resolution UI: *accept server version*, *rebase* (field-level merge with per-collision "keep mine / keep server"), *export draft patch*. Draft state stays client-side (reactive buffers, consistent with the current store style) — never persisted to Kafka.
5. **SSE invalidation via `lib/live.ts`.** Bus/SSE events carrying `revision_token` (a) silently refresh clean views and advance the base token, (b) flag views with dirty local drafts as stale (`hasRemoteUpdate`) with a non-blocking banner. The shared-SSE refactor from Phase 0 is the plumbing.
6. **Qt parity (separate repo).** Mirror the protocol in `EdoClient` as an `OccStateController` — tracked here as the alignment requirement, implemented in the Qt repository.

## Acceptance Criteria
- [ ] **Scenario:** No silent overwrite
	- **Given:** Two clients (e.g. vue-frontend and EdoClient) hold the same base revision token for the FEP crate slice of one project
	- **When:** Client A commits a change, then client B commits with the stale `If-Match`
	- **Then:** B receives `409 Conflict` with the full conflict payload, the committed state of A is untouched, and B's UI offers accept/rebase/discard
- [ ] **Scenario:** Field-level rebase
	- **Given:** A 409 where `field_conflicts` lists exactly one colliding attribute
	- **When:** The user resolves the collision ("keep mine") and retries with the current token
	- **Then:** The commit succeeds and the resulting token is `rev:<seq+1>:sha256:<new digest>`
- [ ] **Scenario:** SSE invalidation
	- **Given:** A client has the slice open, without local edits
	- **When:** Another actor commits (event carries the new `revision_token`)
	- **Then:** The view refreshes and the base token advances without user action; with dirty local edits the draft is flagged stale instead
- [ ] **Scenario:** Restart safety
	- **Given:** socket-ux restarts
	- **When:** A client presents a pre-restart `If-Match` token
	- **Then:** The server still resolves the token correctly (no reset to `rev:0` that would accept stale writes)
